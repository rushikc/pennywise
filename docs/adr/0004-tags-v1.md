# 0004. Tags-v1

Status: Accepted

## Context

An expense had a single `tag` string. Notes and extra labels had nowhere to go, and several clients called `tag.toLowerCase()`, so the field could not disappear in one release.

## Decision

`tags` is a `string[]` and is the source of truth. `tags[0]` is the primary tag. `tag` is a deprecated mirror of `tags[0] ?? null` and is still written. Any short label is a valid primary. `config/tags` is a picker and a spelling hint, not a membership gate. `shared/tagCases.json` is the executable spec for the web app and the Cloud Functions.

## Consequences

Readers tolerate a doc that still has only `tag`. The mirror stays until old cached bundles and deployed functions no longer read it. The migration steps are in [the tags-v1 runbook](../runbooks/tags-v1-migration.md). Extra tags and descriptions are not produced by Gmail ingest.
