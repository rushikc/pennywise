# Tests

| Folder / file | What it covers | Command |
| --- | --- | --- |
| `src/**/*.test.ts(x)` | Web app unit tests (Vitest + jsdom) | `CI=true npm test` |
| `functions/**` | Cloud Functions unit tests (builds the TypeScript parsers first) | `npm test --prefix functions` |
| `e2e/` | Playwright end-to-end tests against the built app and the local Firebase emulators | `npm run test:e2e` |
| `fixtures/` | Synthetic seed data and the emulator seeding helpers used by `e2e/` | `npm run test:e2e:seed` |
| emulators left running for a manual look | Firestore, Auth, and Functions emulators | `npm run test:e2e:emulators` |
| `firestore.rules.test.js` | Firestore security rules | `npm run test:rules` |
| `scripts/migrate/*.test.js` | Migration script unit tests | `npm run test:migrate` |
| `migrateTagsFirestore.emulator.test.js` | Tag migration script against the Firestore emulator | `npm run test:migrate:emulator` |
| `functions/api/api.emulator.test.js` | Pennywise API against the Firestore + Auth emulators | `npm run test:api:emulator` |

One-time, before the first Playwright run: `npx playwright install chromium`.

## Playwright e2e

### One-time setup

```sh
npm install
npx playwright install chromium
```

The Firebase CLI (`npx firebase`) needs Java for the emulators.

### Run

```sh
npm run test:e2e                         # both projects: desktop (1280x800) and mobile (Pixel 7)
npx playwright test --project desktop    # one project
npx playwright test tests/e2e/home.spec.ts
npx playwright show-report               # HTML report after a run
```

`playwright.config.ts` starts both servers on its own:

1. The Firestore, Auth, and Functions emulators (`tests/fixtures/startE2eEmulators.mjs`) after `tests/fixtures/writeApiEmulatorEnv.mjs` writes gitignored `functions/.secret.local` and `functions/.env.demo-pennywise` (files must start with `# pennywise-e2e generated` or the writer refuses to overwrite them). The emulator dotenv parser only accepts `A-Z0-9_` keys, so the starter also injects the kebab-case secret ids into the process environment. Cold start is slower because it also builds Cloud Functions.
2. `vite build --mode e2e` then `vite preview` on `http://127.0.0.1:3100`.

Outside CI, already-running servers are reused. **If you keep `vite preview` running, rebuild with
`npx vite build --mode e2e` after changing anything under `src/`**, or the tests run the old build.

### Never touches live Firebase

- `--mode e2e` ignores every `.env` file and hard-codes the fake `demo-pennywise` project
  (see `E2E_FIREBASE_ENV` in `vite.config.ts`). The app connects to the emulators on
  `127.0.0.1:8080` (Firestore) and `127.0.0.1:9099` (Auth). The Functions emulator listens on
  `127.0.0.1:5001`. Playwright waits until that emulator's health URL answers before the specs start.
- `tests/fixtures/seedEmulator.ts` refuses to run unless `FIRESTORE_EMULATOR_HOST`,
  `FIREBASE_AUTH_EMULATOR_HOST` and `GCLOUD_PROJECT` point at the local emulator and `demo-pennywise`.
- The `window.__pennywiseE2E` test hooks (`src/firebase/e2eHooks.ts`) only exist in the e2e build.

### Fixture data

`fixtures/seed/` is small and fully synthetic. Nothing in it comes from real data.

| File | Contents |
| --- | --- |
| `expenses.json` | 149 expenses (about 45 KB) spread over the months before the fixed clock |
| `config.json` | tag list (10 tags), retired tags (`amenities`, `Movies`) |
| `vendorTags.json` | vendor → tag rules used by auto-tagging |
| `budgets.json` | monthly budgets for a few tags |

The files are generated by `node tests/fixtures/buildSeed.mjs`, which is deterministic
(fixed PRNG seed and a fixed `NOW` of 2026-06-15 12:00 IST). Specs refer to the hand-written
"anchor" expenses (`anchor-*` ids) such as untagged rows, extra tags, a pending duplicate pair,
an out-of-list tag and the retired-tag rows. Keep those ids stable when you edit the generator.
Background rows exist only to fill lists and charts.

Every Playwright worker signs in as its own emulator user (`e2e-user-<n>`). Each test re-seeds that
user's data, so tests run in parallel without sharing state. The browser clock is pinned to the
same `NOW` (`page.clock.install`), so month filters and "this month" totals don't drift.

### What the specs cover

| Spec | Use cases |
| --- | --- |
| `home.spec.ts` | primary chip, extras and description marker; untagged and out-of-list rows; group by tag (case-insensitive); search by extra tag and description; desktop vs. mobile layout |
| `tagDialog.spec.ts` | pick primary, add and remove extras, note, persist after reload; untag-with-extras confirm; keep out-of-list primary; note-only edit keeps concurrent tags; double-click saves once; offline alert; add a manual expense |
| `selection.spec.ts` | merge (survivor and tag default, Untagged clears tags); bulk delete and partial failure; duplicate review confirm and reject |
| `settings.spec.ts` | manage tags (retire, case-insensitive duplicate, re-add, restore retired); auto-tag; Reload All; stale schema forces refetch; clear cache |
| `insights.spec.ts` | budget counts only the primary tag; CSV export columns; tag groups and "not in list" chips |
| `auth.spec.ts` | signed-out demo data; allowlisted vs. not allowlisted users; Google sign-in popup |
| `api.spec.ts` | health and 401s; untagged list; PATCH then Reload All; app note save keeps API extras; primary conflict 409 (desktop only, serial) |

### Skipped by design

- Layout-only tests run on just one project (`test.skip(isDesktop …)` or the reverse).
- The Google popup test runs on desktop only. The emulator's sign-in widget loads its scripts from
  `unpkg.com`, so it needs internet. Set `E2E_SKIP_POPUP=1` to skip it offline.
- `api.spec.ts` runs on desktop only against the Functions emulator. Set `E2E_SKIP_API=1` to skip it.
